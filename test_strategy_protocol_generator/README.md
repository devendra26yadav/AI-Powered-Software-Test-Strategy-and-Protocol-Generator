# TestStrategyProtocolGenerator Crew

Welcome to the TestStrategyProtocolGenerator Crew project, powered by [crewAI](https://crewai.com). This template is designed to help you set up a multi-agent AI system with ease, leveraging the powerful and flexible framework provided by crewAI. Our goal is to enable your agents to collaborate effectively on complex tasks, maximizing their collective intelligence and capabilities.

## Installation

Ensure you have Python >=3.10 <3.14 installed on your system. This project uses [UV](https://docs.astral.sh/uv/) for dependency management and package handling, offering a seamless setup and execution experience.

First, if you haven't already, install uv:

```bash
pip install uv
```

Next, navigate to your project directory and install the dependencies:

(Optional) Lock the dependencies and install them by using the CLI command:
```bash
crewai install
```

## Documentation modes

The Gradio application offers two documentation modes. **General Software** is the default and generates four core documents in a downloadable ZIP. The Test Plan, Protocol, and Summary Report are DOCX files; the Requirements Traceability Matrix is an XLSX workbook. Each document is also available as an individual download:

- `Software_Test_Plan.docx`
- `Software_Test_Protocol.docx`
- `Requirements_Traceability_Matrix.xlsx`
- `Software_Test_Summary_Report.docx`

Both modes use the same generation pipeline for requirement extraction, test design, traceability, consistency checks, and export; mode-specific prompts and templates shape the deliverables.

Before export, the generator runs document quality checks for identifier uniqueness, requirement and risk traceability, test-case duplication, expected-result consistency, execution evidence, coverage gaps, and document metadata. The interface returns a structured validation report, and each ZIP includes the same report as `validation_report.json`. Findings that require input are marked for user review; unsupported execution claims are removed rather than presented as results.

When no test execution evidence is supplied, the summary report marks execution as **Pending / Not Executed** and notes that defects, coverage, and execution conclusions are unavailable.

**Medical Device Software** generates `Software_Test_Plan.docx`, `Software_Verification_Protocol.docx`, `Requirements_Risk_Traceability_Matrix.xlsx`, and `Software_Verification_Summary_Report.docx`. IEC 62304, ISO 14971, ISO 13485, and applicable FDA QMSR expectations are used as design references only; generated documentation does not assert compliance. Missing classifications, execution results, evidence, anomalies, and approvals are identified as not provided, pending, or not assessed rather than inferred. Optional medical-device attachments are not generated by default; include them only when requested or justified by supplied project requirements and source records. The quality-validation report remains in the ZIP as `validation_report.json`.

## Generation speed

Choose a generation speed in the Gradio interface:

- **Demo Mode (Instant Sample)** loads a bundled, pre-generated sample for the selected documentation mode. It makes no AI requests and does not read or process uploaded files. Every sample document and workbook is labeled accordingly.
- **Fast AI Generation** analyzes the uploaded source documents once and creates 5–10 representative, linked test cases in one structured AI request. AI latency depends on the configured provider; the remaining document rendering and ZIP export are performed locally.
- **Full Generation** runs the comprehensive multi-agent workflow and remains the default.

Progress updates distinguish analysis, test-case generation, document creation, and readiness for download. Elapsed times for input reading, AI generation, document assembly and validation, individual document rendering, ZIP creation, and total generation are logged.
